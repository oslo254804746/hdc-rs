# hdc-rs 0.2.0 validation review

This note records the validation evidence for the `v0.2.0` release. The
offline suite verifies protocol framing and client behavior; it does not
replace acceptance on an authorized HarmonyOS/OpenHarmony device.

## Offline evidence

The following checks passed from the release tree on 2026-09-05:

```text
cargo fmt --all -- --check
cargo check --workspace --all-targets --all-features --locked
cargo test --workspace --all-features --locked
cargo clippy --workspace --all-features --locked -- -D warnings
cargo +1.71.0 check --workspace --all-targets --all-features --locked
cargo publish -p hdc-rs --registry crates-io --dry-run --allow-dirty --locked
```

The test run reported 43 passing unit/doc tests and 4 passing application
protocol regression tests. Two blocking-client tests and 16 real-device tests
were ignored by design. The pure validation tests in the real-device target
also passed.

The Python protocol regression script is intended to run against an installed
wheel (`tests/python_protocol_test.py`). Building that wheel requires maturin;
the release workflow builds wheels on its matrix and publishes them to PyPI
when the version tag is pushed.

## Device acceptance boundary

Device-dependent tests remain ignored by default. They require:

- a running HDC server (default `127.0.0.1:8710`),
- an explicit `HDC_TEST_DEVICE_ID`, and
- an authorized HarmonyOS/OpenHarmony device.

File, forwarding, hilog, and shell acceptance use a disposable remote
directory. App lifecycle tests additionally require an explicitly supplied,
disposable `HDC_TEST_HAP` and matching `HDC_TEST_BUNDLE`; they are opt-in via
`HDC_ALLOW_APP_CHANGES=1`. Tests that can disrupt the target require
`HDC_ALLOW_DISRUPTIVE=1`. These safeguards prevent a release check from
silently selecting or modifying a personal device.

The relevant Rust tests are in `hdc-rs/tests/real_device_test.rs`, and the
Python smoke test is `tests/python_real_device_smoke.py`. Run only selected
tests serially after configuring the required environment variables.

## Release interpretation

The offline results support publishing the `hdc-rs` crate and the Python
wheel artifacts. No claim of real-device coverage is made until the explicit
device acceptance prerequisites above are satisfied.
